# Approved-Lesson Live Qualification

`run.py` exercises the local application through its public HTTP surface in a
disposable PostgreSQL and filesystem topology. It combines focused browser and
headless checks, restarts the application without reseeding, and removes only
runner-owned resources in its cleanup path. It is cumulative qualification,
not a substitute for focused domain, contract, application, architecture, or
security tests.

The learning-lineage phase derives exact lesson and completion selectors from
live public responses. It compares the reviewed generated TypeScript client
with an ordinary authenticated HTTP client, repeats both accepted reads,
checks confidential missing-session and invalid-selector denials, and requires
the complete canonical views to remain exact after a normal restart. After the
first deterministic Audit reconciliation, non-Identity database fingerprints
and the bounded application-data tree must remain unchanged during lineage
reads. Replay tests vary valid graph counts, order, Unicode identifiers,
timestamps, and incomplete links so the live check does not freeze an
incidental fixture shape.

The phase does not add a learner-facing lineage page or claim export,
retention, recovery, public hosting, or managed-cloud qualification.

The accountable-history phase reuses those exact live lesson and completion
selectors. It compares generated-client and ordinary authenticated HTTP
inspection and portable-export documents for both roots, repeats every
operation, checks confidential missing-session, query, and guessed-completion
denials, and requires complete document and digest equality after a normal
restart. A selector-only browser phase discovers the completion through the
public completion view, which may refresh its existing rebuildable Learner-model
projection. The runner freezes database and file fingerprints after that phase
and before the first accountable-history call, then requires every generated,
ordinary HTTP, and headless inspection/export operation to preserve every
non-Identity schema and the bounded application-data tree.

Replay tests vary entry, transformation, gap, diagnostic, redaction, Unicode,
timestamp, and root shapes and reject client disagreement, private fields,
missing exact root entries, impossible dates, and restart drift. Focused Web
evidence remains responsible for learner-facing rendering, keyboard/focus,
reflow, themes, accessibility, and local download cleanup. The cumulative phase
does not claim retained export, legal/compliance meaning, tenant/admin access,
public hosting, recovery, or managed-cloud behavior.
