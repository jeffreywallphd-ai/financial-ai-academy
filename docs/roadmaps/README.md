# Implementation Roadmaps

- Status: accepted
- Canonical for: roadmap lifecycle and sequencing authority

Roadmaps sequence bounded approved work. They do not define product meaning, architecture, risk policy, or contract semantics.

Use:

- `active/` for accepted work in progress,
- `archive/` for completed or superseded roadmaps.

A roadmap identifies decisions, increments, acceptance evidence, documentation impact, and stop conditions. Proposed or reviewed roadmaps do not authorize implementation by themselves.

Shape capabilities, vertical slices, agent work packets, and decision requests in the [automated development planning area](../planning/README.md). When sequencing is accepted, a roadmap links those source artifacts and they link back to the roadmap. Roadmap acceptance does not substitute for packet planning approval, implementation approval, or a current explicit implementation request. External, destructive, production, publication, or credentialed actions retain separate authority.
