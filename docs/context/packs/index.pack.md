# Context Pack: Index

## Purpose

Baseline context for every non-trivial task.

## Preserve

- One shared local/cloud domain and application core
- Python module-first modular monolith and TypeScript web boundary
- Explicit versioned public contracts and provider-neutral domain models
- Deterministic policy authority around AI/ML
- PostgreSQL transactional and Parquet/DuckDB analytical separation
- Provenance for learner, market-data, dataset, model, and portfolio evidence
- Educational scope without personalized financial-advice claims
- Canonical semantic design tokens and iconography for interface work; mockups remain directional
- One delivery approval for a complete CAP package whose manifest enumerates every slice; refine slices and packets just in time without approval while they remain inside the package
- Keep explicit durable decisions and external/destructive authority separate from the CAP planning approval
- Approval and reviewer records remain only in the ignored local ledger, never tracked artifacts or summaries
- Community retained evidence follows ADR-0008's private-host, coordinated-recovery-set, empty-target restore, and no-RPO/RTO boundary; managed-cloud recovery remains unresolved
- Initial application artifacts follow ADR-0009: Python 3.14/FastAPI 0.141/Pydantic 2.13 and a Node 24/TypeScript 7/React 19/React Router 8 Data Mode/Vite 8 static client with no Node production server
- ADR-0012 assigns learning-initiated and independent project workspaces and immutable snapshots to Project while Content/Curriculum retain learning authority and Assessment retains submissions and completion evidence
- Projects may link to multiple Portfolio-owned or other domain-owned resources without copying their state; live Portfolio behavior remains gated on accepted Portfolio contracts
- Project datasets, notebooks, code, environments, and results remain inert untrusted evidence under ADR-0011; learner-managed execution does not authorize a platform or provider runtime
- Planning advice, readiness, and roadmaps never replace CAP authority; packets execute in dependency order, conforming detail may evolve, and material CAP drift requires renewed CAP approval
- ADR-0014 governs adaptive competency estimation and guidance through independently versioned estimate/publication policies, deterministic eligibility and fallbacks, calibrated abstention, phased champion-challenger qualification, and separate consented experiment review
- ADR-0015 assigns canonical financial data to Market data, simulated portfolios/backtests to Portfolio, and reusable deterministic calculations to an owner-declared versioned pure method registry without an Analysis module

## Workflow

Read `docs/README.md`, apply the change-impact matrix, select only task-relevant packs, consult decision readiness, inspect current implementation/tests, and report verification plus known gaps.

## Authority

This pack is derived. Canonical product, domain, architecture, ADR, risk, security, and standards sources win.
