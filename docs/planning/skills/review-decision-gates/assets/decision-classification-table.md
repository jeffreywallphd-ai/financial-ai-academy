# Decision Classification Table

| Decision | Readiness | Viable options | Recommendation | Blocking DEC |
| --- | --- | --- | --- | --- |
| Decision name | `ready`, `constrained`, `proposed`, or `decision-required` | `A. First option; B. Second option` | `Option A — concise reason`, or `Defer — missing evidence` | `DEC-####`, or `None — canonical authority` |

## Rules

- Include one row for every material decision reviewed.
- For `proposed` and `decision-required` rows, list at least two materially distinct options that comply with verified constraints. Exclude choices already prohibited by canonical authority.
- For `ready` and `constrained` rows, state the accepted path as the only viable option and cite its canonical authority after the table.
- Keep option labels stable between the table and the linked decision request.
- Name the recommended option explicitly. Use `Defer` when evidence or qualified review is insufficient.
- Use a blocking `DEC-*` ID for unresolved choices. Use `None` only when accepted canonical authority fully determines the path within scope.
- Present related unresolved `DEC-*` rows as one closed decision set and request one response mapping every listed decision to its chosen option.
- Record one local decision per `DEC-*` after that response. New or materially revised decisions are not covered.
