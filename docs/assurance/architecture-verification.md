# Architecture Verification

- Status: current
- Canonical for: architecture-evidence routing

The current invariant-to-evidence map is maintained in `docs/architecture/assurance/architecture-verification.md`.

At this foundation stage, application architecture checks are gaps because no application code, generated contracts, or deployment manifests exist. Documentation/context structure, design-system assets, planning integrity, planning-tool behavior, skill compatibility, and prompt-level planning routing have direct evidence through `python dev-tools/agent/check_ready.py`. New implementation must add or update the owning verification row and focused boundary evidence in the same change.

Changed learner-facing copy has direct, bounded evidence through the
candidate-bound learner-language check, its anti-rigidity corpus, fixed
readiness integration, and tracked affected-check selection. Checker or rule
changes select direct tests and controlled full-scope qualification. Advisory
wording, whitespace, CSS, generated clients, fixtures, documentation, and
unrelated code do not become learner-language blockers or trigger aggregate
readiness through those selection rules.

The Adaptation activity-launch boundary has direct evidence through the closed
Draft 2020-12 schema, independent compatibility runner, approved and denial
corpus, pure-policy unit tests, existing Navigation-state conformance suite,
and module-boundary tests. These checks prove exact graph/projection closure,
server-owned lesson destinations, bounded refusal without destination leakage,
flexible graph shapes, and the absence of provider, model, persistence, or
framework authority. API and browser qualification remain intentionally
unclaimed until the later SLI-0024 packets.

Planned verification categories:

- module dependency direction,
- contract schema/catalog integrity,
- deterministic generation,
- provider conformance,
- local/cloud shared-core composition,
- AI authority boundaries,
- financial-data normalization and calculation invariants,
- documentation/context integrity.
